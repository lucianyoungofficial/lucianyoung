搭建这个网站本身就是一个工程实践。从 Hugo 初始化、GitHub 仓库、Vercel 部署，到域名配置、HTTPS、版本兼容，每一步都遇到了问题，每一步也都留下了记录。

## 文档不是负担

以前我觉得写文档是额外的工作量。代码写完了，功能跑通了，为什么还要花时间写文档？

后来我发现，**没有文档的知识不是真正的积累**。

一个月前修好的 bug，一个月后已经忘了怎么修的。当时的思路、踩过的坑、为什么选择 A 方案而不是 B——这些信息如果不写下来，就等于没做过。

## 文档即思考

写文档的过程，其实是重新审视自己工作的过程。

当你试图把一件事情写清楚，你会发现：

- 有些地方你其实没想明白
- 有些步骤可以更简洁
- 有些决策当时没有充分的理由

**Writing is thinking.** 说不清楚的事情，往往是因为没有想清楚。

## 三个层次

我现在的文档体系分为三层：

| 层次 | 载体 | 用途 |
|------|------|------|
| 最终成果 | 网站 | 展示已完成的项目和思考 |
| 工程过程 | GitHub + docs/ | 设计决策、排障记录、技术细节 |
| 修改痕迹 | Git Commit | 每一步改了什么 |

三者各司其职，不需要互相替代。

## 长期主义

这个网站的目标不是短期内塞满内容，而是持续记录真正有价值的工程实践。

一篇完整的项目回顾，比十篇浅尝辄止的笔记更有价值。

> Don't count projects. Make projects count.
